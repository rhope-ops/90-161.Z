## Findings

1. **Windows blocked one step script once, and the PFM was not told.** Step 29 (`90161Z-T26-endorse-r3.ps1 -Part Make -Label after`) stopped at once with `UnauthorizedAccess`, "running scripts is disabled on this system". The same file ran 6 times before and once a few seconds later (step 31), from the same RADE window, with no change to the file. Cause: not known. Assumption (confidence: low): a Group Policy refresh rewrote the execution policy for a moment. The end card shows only the first problem (T21) and "N more", so the block was not on the screen. The help text "Check that the RADE folder is in your own OneDrive and not read-only" is wrong for a policy block: the pattern `denied|UnauthorizedAccess` in engine part 02 matched it. Fix: RADE engine (one retry of a step that a policy blocked before its first line, the policy scope list in the log, its own help text, and the block named on the end card).
2. **The small sign-in window has a known cause.** T22 makes its process DPI-aware (`SCALE dpi-aware=yes`) before it signs in. In a DPI-aware process, Windows draws the PnP sign-in window at its real 1024 x 768 pixels; in every other step Windows stretches it 1.5 times on this 150 % screen (1536 x 1152 on a 1920 x 1128 work area). `size=` reads 1024x768 in both cases, so the line does not show the difference. Confidence: high for the mechanism, medium that this is what the PFM saw (not reproduced). From engine-v35 to engine-v43 the size watch made the window 480 x 360; engine-v44 removed the watch (R44 finding 1), so since R45 each sign-in window covers most of the screen. Fix: the sign-in block makes the step process DPI-aware before `Connect-PnPOnline`; it does not move or size the window.
3. **The dry-run answer did not match the screen text.** The choice said "4 rows, 3 from the Recycle Bin"; the screen said "4 rows would come back (3 from the Recycle Bin, 1 as new rows)". That is the expected dry run, so Restore read the backup and the Recycle Bin correctly. The PFM chose "Something else", and the 4 steps after it were skipped, also "Close the second window": the round then gave no step to close it. Restore's write is still not proved. Fix: choices copied from the screen text; the close step runs after any result.
