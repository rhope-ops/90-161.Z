Tiers in F03 (r2 and r3, weekdays relative to the suspense, PFM 2026-11-14): Escalation from pfm_EscalationLagDays working days after; Warning from the suspense day; Reminder from pfm_ReminderLeadDays weekdays before. Weekday arithmetic assumes the suspense falls on a weekday (the default suspense always does). F03 r4 (R22, R21 finding 2): a Saturday or Sunday run counts the working days from the Friday before (Today_weekday), as F06 does; r3 ended 20 working days from a Saturday on a Monday. F03 r5 (PFM 15 Nov 26: the test escalation e-mail did not arrive in 3 rounds while its log row was written): the log row's Event Details ends with the mailbox that sent the e-mail (the shared mailbox or the flow owner mailbox), and T18 r3 reports it. Each tier is sent once per row (a Reminder Sent row in the Activity Log is the memory). The flow never changes an Endorsement Status.

Every flow in the slice (F03 r3, F05 r2, F06 r1; PFM 14 Nov 26): the steps sit in a Try scope. The first step stops the run when Flows paused is Yes. If a step fails or times out, the flow e-mails the alert address (flow, start time, the failed step and its error, and what to do: fix the cause, then Resubmit the run; Resubmit starts again from the beginning and adds only what is missing). The e-mail links to the failed run on the DoD portal (PFM 1A, 14 Nov 26: tests/check_flow_solution.py allows that one host). Flow IDs stay the same across revisions (scripts/build_flow_solution.py flow_guid), so a new import upgrades a flow instead of adding a copy. Flow solutions carry the flow JSON without indents (300 KB round limit). Every "Update item" sends item/Title (R20 finding 1; tests/check_flow_solution.py). After the failure e-mail the run ends as Failed (End_as_failed), so it shows red in the run history and can be resubmitted; without it the handled run would read Succeeded. F05 r2 writes Coordination Round 1 on every row it makes (D4; a later round needs the app's Restart coordination, not built).

Why F02 uses a recurrence: the 6-month review task opens on a date, not on an edit, so a daily check serves both the date calculation and the task. An item trigger on Product Index would also need a timer. The same weekday 07:00 schedule as F03 is reused (open choice 7).

## F05 routing: open points (draft)

- a. The gate runs on an edit of the Publications row. An endorser answer alone does not start it; the PFM's "All Comments Adjudicated = Yes" edit does. Option: a second trigger on PFM Endorsements (or a child flow) if answers arrive after that edit.
- b. Steps are found by StepNumber 6 and 7 (seed data). A wing that renumbers its steps must change the flow.
- c. The Privacy office is mandatory, so it also gets a Formal Coordination row, although step 5 is a separate Privacy review. Option: skip the Privacy role at step 6 when a Privacy Review row exists.
- e. If PFM Offices has no active mandatory office (other than Legal), F05 creates no rows and the step waits with no warning. Option: log or e-mail the PFM.
- f. Fixed in r2: F05 adds only the rows that are missing, office by office (matched by title suffix; renaming an office makes a second row). Any answer other than Not Started (for example Concur With Comment) counts as answered.
- d. The flow creates the rows, so with "edit own rows" (10A) endorsers answer in the app through an app flow; the flow only alerts them to open the app (PFM, 2026-11-14; not built yet).

## Open design choices

1. Endorsement routing: decided A (PFM S5A, 2026-11-14): F05.
2. Polling interval of the F01 trigger (draft: 1 minute) and whether F01 should log every edit instead of state changes.
3. Decided (PFM, 2026-11-14): 20 working days (weekdays only), no holiday list, no hand edits (pfm_SuspenseWorkdays).
4. Suspense start: the draft starts it on the first weekday run after the row exists. Options: start when the step moves to Formal Coordination (needs routing); use the row's Created date. Legal rows get no default suspense yet (F05 creates them; their start could be the row's Created date). Privacy Review rows do get one.
5. 5.2.2 (30 calendar days) is applied to the Guard Applicability and Reserve Applicability roles only; the process model says whether it covers wing-to-unit coordination is open (gap check).
6. Decided (PFM, 2026-11-14): reminder 5 weekdays before, escalation 3 working days after, copied to the AO and Requester; sent from the shared mailbox in pfm_SharedMailbox (Send As), else from the flow owner's mailbox (the fallback for wings without Send As).
7. Run time of F02 (draft: same as F03) and whether Date columns are date-only (the flows read the first 10 characters; a date-time column in Central could shift a day).
8. Done in F03 r3: the tiers use the later of DueDate and ExtensionDate (5.2.1).
9. "Open action" for F04 and for stage counts: PFM Publications has no closed flag, so F04 lists every row. Options: exclude rows at the last step; add a closed status or date.
10. F04 recipient: typed at run time (draft). Option: the person who runs it (needs the Office 365 Users connector, "Get my profile (V2)").
11. List names: titles (draft) or list GUIDs in the environment variables. GUIDs are safer if a list is renamed.
12. F02 also skips opening a second Periodic review when one was opened in the current cycle and already answered; the brief says only "if none open".
13. E-mail text has no link to the item (the list URL names are not in the repo). Option: add a pfm_ list-URL variable.
14. The publisher is PFM with option value prefix 89127, as in the PFM's R18 export (flow/solution/export-sample); a new environment creates PFM with these values.
15. Solution XML, operation IDs and the `Publication/Id eq N` filter style are unverified until a first import (see the top of this file).
