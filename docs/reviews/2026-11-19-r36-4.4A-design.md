# Rule 4.4A warning: design (R36)

Status: DRAFT for the PFM's approval (DECISIONS 19 Nov 26: "Claude writes a design for R36; the PFM approves it before the build"). Written 19 Nov 26, about 15:40 Central.

## The rule

DEC 2026-11-12 (4.4A): the app warns when a T-0, T-1 or T-2 waiver in PFM Waivers names a wing approver. Source: DAFMAN 90-161 Attachment 10, Table A10.1 (coverage rows part-6.md, refs 7305, 7368, 7442):

- T-0: not waivable by the DAF; relief goes through command channels to the HQ DAF OPR.
- T-1 and T-2: the MAJCOM/CC waives; for the ANG, NGB/CF, delegable no lower than ANGRC/CC (T-2 also to NGB Directors).
- T-3: the Wing or Delta CC waives, delegable to a squadron CC. No warning.

So a wing person as the Waiver Approver of a T-0, T-1 or T-2 waiver is almost always an error in the record or in the waiver.

## What counts as a wing person

A person who is the Leader of any row in PFM Offices (`Leader`, a Person column). This needs no directory lookup and no search outside the site (project rule "No reconnaissance"). Limit: a wing commander who is not listed as a Leader in PFM Offices is not caught. The PFM keeps PFM Offices current anyway (Q6, Q13).

## Design

New flow F08 "Waiver tier check" (r1), in the app solution, same pattern as the others (Try scope, PFM Settings read, Flows paused stop, failure e-mail, End_as_failed).

| Part | Choice |
|---|---|
| Trigger | PFM Waivers "When an item is created or modified", checked every 15 minutes (as F01; a waiver is not urgent) |
| Condition | Tier is T-0, T-1 or T-2, and Waiver Approver is set, and the approver's e-mail equals the Leader e-mail of any PFM Offices row |
| Action | 1. An Activity Log row, Event Type "Waiver Warning" (a new choice: T19 adds it to PFM Activity Log; the closest existing choice is "Other"), title "Waiver tier warning: W<ID>", details: tier, the Table A10.1 approver for that tier, and "the Waiver Approver is a wing leader". 2. One e-mail to the alert address (the same address as the failure e-mails) with a link to the waiver row. |
| Once only | The flow sends nothing when an Activity Log row "Waiver tier warning: W<ID>" with the same tier and approver exists (the F03 memory pattern), so an unrelated edit does not warn again; a change of tier or approver warns again. |
| Data change | None. The flow never changes the waiver row: a warning, not a block. |
| Test hook | With Test mode = Yes, the e-mail goes to the alert address only (it does anyway); no other change. |

Not in scope: T-3 delegation limits (squadron CC floor, Table A10.1 T-3) and the existing "Delegation Letter Link is required when Approved by Delegation is Yes" rule; each can join F08 later.

## Test (R36 or the next round with room)

Expected: exactly 1 warning row and 1 e-mail.
